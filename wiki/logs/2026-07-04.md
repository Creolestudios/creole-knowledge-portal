# Project Log — 2026-07-04

## Added
- **Live Google Drive publishing** (`lib/blog-roulette/google-drive.ts`): new `uploadBlogAsGoogleDoc()` uploads a blog's `body_html` directly to Drive as a **native Google Doc** (`mimeType: application/vnd.google-apps.document`, source `text/html`). Drive performs the HTML → Docs conversion on upload — no Pandoc/`.docx` intermediate step.
- **Migration** `20260704120000_blog_roulette_drive_link.sql`: adds `drive_url` and `drive_file_id` columns to `roulette_blogs`, denormalized from `roulette_publish_logs` for quick UI access. **Not yet applied to the remote Supabase project** — needs to be run manually (no local Supabase CLI/config in this repo).
- **UI**: `app/blog-roulette/page.tsx` now shows a "View Google Doc" link (using `drive_url`) on `PUBLISHED` cards, and a "Retry Publish" button on `PUBLISH_FAILED` cards that calls the existing `POST /api/blog-roulette/[id]/publish` retry endpoint.
- **Tests**: `lib/blog-roulette/google-drive.test.ts` and `lib/blog-roulette/publisher.test.ts` — mock `googleapis` and `./google-drive` respectively, per `coding-standards.md` (never hit real APIs in unit tests). 8 new tests, all passing.

## Changed
- **`lib/blog-roulette/publisher.ts`**: removed the hardcoded bypass block (`fileId = 'bypassed_gdrive'`, `webViewLink = 'bypassed_link'`) that had existed since the Drive integration was first introduced in commit `2e14a4e` and had never actually run. `runPublishPipeline()` now really calls `uploadBlogAsGoogleDoc()` → `shareBlogWithMarketing()` and persists the real file ID / link to both `roulette_publish_logs` and `roulette_blogs`.

## Technical Notes / Decisions
- **Chose native Google Doc import over Pandoc + `.docx` upload.** `lib/blog-roulette/converter.ts` (Turndown → shells out to a system `pandoc` binary) is no longer used in the live pipeline — `pandoc` was not installed on this host and shelling out to a system binary is fragile for containerized/serverless deployment. `converter.ts` is left in place but unused; consider deleting if this direction is confirmed permanent.
- The pipeline still requires real env values to actually run end-to-end: `DRIVE_FOLDER_ID`, `DRIVE_SERVICE_ACCOUNT_KEY_JSON`, `MARKETING_NOTIFY_EMAILS` (documented in `.env.example`, not yet set in `.env.local` as of this log — user must provision a Google Cloud service account + share the target Drive folder with it).
- `wiki/blog-roulette-flow.md` step 7 ("Publishing: Markdown -> Pandoc -> .docx -> Google Drive API") is now **stale** — publishing is HTML -> Drive-native-Google-Doc, no Pandoc/Markdown step. Needs updating once this is confirmed as the permanent approach.
- Migration file was created but **not run against the Supabase project** — this repo has no `supabase/config.toml` or CLI access; someone with DB access needs to apply `20260704120000_blog_roulette_drive_link.sql` manually (e.g. via the Supabase SQL editor) before `drive_url`/`drive_file_id` writes will succeed.
