# August 27, 2026

## Fix Synthesis Pipeline Digest ID Error
- **Issue**: The frontend was showing the error `Synthesis pipeline error: Pipeline finished without a digest id` when users tried to synthesize their daily morning blog.
- **Root Cause**: When the background blog fetching pipeline successfully discovered `0` new articles (e.g. because they were all already served or career-fluff), it passed an empty article list to `_generate_digest`. The generator would then return an empty string for `digest_id`, causing `publish_digest` to also return an empty string. The pipeline orchestration in `run_celery_pipeline_and_wait` saw the empty result and threw a confusing `RuntimeError`.
- **Fix**: 
  - Updated `_generate_digest` in `src/workers/generator_tasks.py` to bypass the early `return ""` when no articles are found and instead proceed to the synthesis engine.
  - Updated `synthesize_digest` in `src/generator/synthesizer.py` to gracefully bypass the `_enforce_min_length` check when `articles` is empty. This allows the generator to cleanly produce and return the ID of a structured "fallback" digest rather than crashing the pipeline.
  - Added unit test coverage for the fallback digest mechanism in `tests/unit/test_generator_fallback.py`.
- **Status**: Fixed on branch `fix-synthesis-pipeline-digest-id-error` and successfully deployed.
